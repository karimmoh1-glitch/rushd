# Rushd for desktop (macOS + Windows)

Rushd for desktop is a **secure native wrapper around the hosted Rushd web app**. It opens
https://therushd.com/dashboard in its own window, with the platform's system web view
(WKWebView on macOS, WebView2 on Windows). It is built with [Tauri v2](https://v2.tauri.app).

It is **not** an offline or local-first app. All data and features come from the live website,
so **it needs an internet connection**. When Rushd can't be reached, the app shows a bundled
offline page with a **Try again** button.

- Identifier: `com.therushd.app` · Product name: `Rushd` · Version: `0.1.0`
- Bundle size: about 3 MB (`.app`), about 1.5 MB (`.dmg`)

## How it works

```
desktop/
├── package.json            # Tauri CLI (devDependency) + scripts
├── dist/                   # bundled local page: launcher + offline screen (no Tauri APIs)
│   ├── index.html
│   ├── launcher.js
│   └── style.css
├── scripts/make-icon.mjs   # renders the placeholder icon source (no dependencies)
└── src-tauri/
    ├── Cargo.toml / Cargo.lock
    ├── tauri.conf.json     # app metadata, CSP for the local page, bundle settings
    ├── capabilities/       # deliberately empty: no IPC permissions for anyone
    ├── icons/              # generated by `tauri icon` from icons/source.png
    └── src/lib.rs          # window, navigation policy, menu
```

1. The window opens on the bundled launcher page (`dist/index.html`). It sends one
   `no-cors` request to `https://therushd.com/`. If that works, it replaces itself with
   `https://therushd.com/dashboard`. If not, it shows "Can't reach Rushd" with **Try again**.
   It also retries automatically when the OS reports the connection is back.
2. **View → Reload** (⌘R) on macOS goes back through the launcher with `?next=<current path>`.
   If the connection dropped, you get the offline page instead of a blank window.
   **View → Go to Dashboard** (⇧⌘H) returns to `/dashboard`.

### Security model

- **No native access for the website.** The app registers no custom commands. The only
  capability file (`src-tauri/capabilities/default.json`) grants no permissions and has no
  `remote` section, so `https://therushd.com` and any other remote origin can't call Tauri IPC.
  The opener plugin is used only from Rust.
- **Navigation allowlist (Rust, `on_navigation`).** Only `https://therushd.com/**` (default
  port) and the bundled local page may load in the window. Other `http(s)`, `mailto:` and `tel:`
  links open in the system default browser or handler. Everything else is blocked, including
  `file:`, `data:`, custom schemes and other hosts.
- **Popups (`on_new_window`).** `window.open` and `target="_blank"` never create a new web view.
  Rushd URLs open in the main window. Anything else opens in the system browser.
- External opens are rate-limited to one per second. A single click can be reported twice, and
  a misbehaving page must not be able to spam browser tabs.
- **Downloads** are allowed only from `https://therushd.com`, from `blob:` URLs created by the
  Rushd page, or from `data:` URLs. They are saved to the Downloads folder.
- **Devtools** are on only in debug builds (`devtools(cfg!(debug_assertions))`, and the
  `devtools` Cargo feature is not enabled).
- **CSP** for the bundled local page (in `tauri.conf.json`): `default-src 'none'; script-src
  'self'; style-src 'self'; img-src 'self' data:; connect-src https://therushd.com;
  base-uri 'none'; form-action 'none'`. The remote site's own CSP and headers apply to the
  remote site.
- File drag-and-drop is passed through to the web page so upload drop-zones work. Tauri's
  native drop handler is disabled.

Platform note: on macOS, WebKit runs the navigation check for **iframes too**. A third-party
iframe embedded by the site (for example a payment or video widget) is blocked and opened in the
browser instead. On Windows the check covers top-level navigations only, so iframes load
normally. If Rushd starts embedding third-party iframes, or adds a third-party sign-in/redirect
flow (OAuth, hosted checkout), add those hosts in `src-tauri/src/lib.rs`
(`is_app_url` / `is_inert_frame_url`). Today the login flow stays on `therushd.com`.

## Build locally

Requirements: Node 20+, Rust stable (1.90+). On macOS you also need the Xcode Command Line Tools.
On Windows you need the MSVC build tools and WebView2, which ships with Windows 10/11.

```bash
cd desktop
npm install
npx tauri dev        # debug build with devtools (right-click → Inspect)
npx tauri build      # release build for the host architecture
cd src-tauri && cargo test   # unit tests for the URL policy
```

Outputs (macOS, Apple Silicon):

- `desktop/src-tauri/target/release/bundle/macos/Rushd.app`
- `desktop/src-tauri/target/release/bundle/dmg/Rushd_0.1.0_aarch64.dmg`

Universal macOS build (needs both Rust targets, for example via rustup:
`rustup target add aarch64-apple-darwin x86_64-apple-darwin`):

```bash
npx tauri build --target universal-apple-darwin
```

Windows (run on Windows): `npx tauri build --bundles nsis,msi` produces
`target/release/bundle/nsis/Rushd_0.1.0_x64-setup.exe` and `.../msi/Rushd_0.1.0_x64_en-US.msi`.

### Icons (placeholder)

The current icon is a **placeholder**: a deep-indigo (`#3730a3`) rounded square with a white
"r", drawn by `scripts/make-icon.mjs`. To use real brand art, replace
`src-tauri/icons/source.png` with a 1024×1024 PNG and run
`npx tauri icon src-tauri/icons/source.png`. Then delete the generated `android/`, `ios/` and
`Square*`/`StoreLogo` files, which are not needed for desktop. To re-render the placeholder,
run `npm run icons`.

## Releases (GitHub Actions)

Workflow: `.github/workflows/desktop-release.yml`.

1. Bump `version` in `desktop/src-tauri/tauri.conf.json`, plus `desktop/package.json` and
   `desktop/src-tauri/Cargo.toml` to keep them in sync. Commit.
2. Tag and push: `git tag desktop-v0.1.0 && git push origin desktop-v0.1.0`.
   The workflow fails early if the tag doesn't match `tauri.conf.json`.
3. CI builds:
   - **macOS universal** (Apple Silicon + Intel): `Rushd_<ver>_macos_universal.dmg`, plus
     `.app.tar.gz`
   - **Windows x64**: `Rushd_<ver>_windows_x64-setup.exe` (NSIS, per-user install, no admin
     needed) and `Rushd_<ver>_windows_x64.msi`
4. CI publishes a GitHub **pre-release** named `Rushd Desktop v<ver>` with those files. The
   installers are also attached to the workflow run as artifacts.

Running the workflow manually (**Actions → Desktop release → Run workflow**) builds the same
installers as workflow artifacts **without** creating a release. Use it for test builds.

Windows MSI needs a purely numeric version (`1.2.3`, not `1.2.3-beta`). The NSIS `.exe` is the
recommended download.

## Code signing and notarization: currently missing

Builds are currently **unsigned** test builds. macOS gets an ad-hoc signature (`signingIdentity:
"-"`), which keeps Apple Silicon from calling the app "damaged" but does not identify a
developer. The workflow already has hooks for signing. Add the GitHub secrets below and the next
tagged build is signed. If a secret is absent, it is simply skipped.

### macOS: Developer ID + notarization

You need an **Apple Developer Program** membership ($99/yr) and a **Developer ID Application**
certificate.

| Secret | Value |
| --- | --- |
| `APPLE_CERTIFICATE` | base64 of the exported `.p12` (Developer ID Application cert + private key): `base64 -i cert.p12 \| pbcopy` |
| `APPLE_CERTIFICATE_PASSWORD` | password set when exporting the `.p12` |
| `APPLE_SIGNING_IDENTITY` | e.g. `Developer ID Application: Rushd Inc (TEAMID1234)` |
| `APPLE_ID` | Apple ID email used for notarization |
| `APPLE_PASSWORD` | an **app-specific password** for that Apple ID (appleid.apple.com) |
| `APPLE_TEAM_ID` | 10-character Team ID |

Set them all together. A partial set, such as `APPLE_ID` without a certificate, makes
notarization fail. Instead of `APPLE_ID`/`APPLE_PASSWORD`, Tauri also accepts an App Store
Connect API key (`APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH`). To use one, add
those to the workflow's export step.

### Windows: Authenticode

Option A: an OV/EV code-signing certificate as a `.pfx` file. It is supported by the workflow
today:

| Secret | Value |
| --- | --- |
| `WINDOWS_CERTIFICATE` | base64 of the `.pfx` (`[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx"))`) |
| `WINDOWS_CERTIFICATE_PASSWORD` | the `.pfx` password |

The workflow imports it and passes `certificateThumbprint`, SHA-256 digest and a DigiCert
timestamp server to `tauri build`. Most certificates issued since 2023 live on hardware tokens or
cloud HSMs and cannot be exported as a `.pfx`. In that case use option B.

Option B: **Azure Trusted Signing** (Microsoft's managed signing service, usually the simplest
for new publishers). Set `bundle.windows.signCommand` in `tauri.conf.json` to run
`trusted-signing-cli` (see the [Tauri Windows signing guide](https://v2.tauri.app/distribute/sign/windows/)),
and add `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` and `AZURE_TENANT_ID` as secrets passed to the
build step.

### What users see without signing

- **macOS**: Gatekeeper blocks the first launch ("Apple could not verify 'Rushd' is free of
  malware", the "unidentified developer" warning). On macOS 14 and earlier, **right-click (or
  Control-click) the app → Open → Open**. On macOS 15 (Sequoia) and later, the right-click route
  no longer works. Try to open the app once, then go to **System Settings → Privacy & Security**,
  click **Open Anyway** next to the Rushd message, and confirm. This is needed only once per
  version.
- **Windows**: SmartScreen shows "Windows protected your PC". Click **More info → Run anyway**.
  Even signed builds can trigger SmartScreen until the certificate builds reputation; EV
  certificates and Azure Trusted Signing build it faster.

## Auto-updates: not enabled (how to enable later)

The Tauri updater is intentionally **off**. It requires an update-signing keypair that hasn't
been created yet. This is separate from Apple/Windows code signing. To enable it:

1. Generate the keypair (keep the private key secret and backed up; losing it means existing
   installs can never update):
   ```bash
   cd desktop && npx tauri signer generate -w ~/.tauri/rushd-updater.key
   ```
2. Add GitHub secrets `TAURI_SIGNING_PRIVATE_KEY` (the private key file's contents) and
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. The workflow already forwards them when set.
3. Add the plugin: `cd src-tauri && cargo add tauri-plugin-updater tauri-plugin-dialog tauri-plugin-process`.
   Register them in `src/lib.rs`, then check for updates **from Rust** at startup, for example
   `app.updater()?.check().await` followed by `download_and_install`, and ask before relaunching.
   Do **not** add `updater:*` permissions to the capability file. The website must not be able
   to trigger updates.
4. In `tauri.conf.json`, set `"bundle": { "createUpdaterArtifacts": true }` and add:
   ```json
   "plugins": {
     "updater": {
       "pubkey": "<contents of ~/.tauri/rushd-updater.key.pub>",
       "endpoints": ["https://github.com/<owner>/<repo>/releases/latest/download/latest.json"]
     }
   }
   ```
5. In the workflow, keep `includeUpdaterJson` at its default (true) so `latest.json` is
   uploaded. Note that GitHub's `releases/latest` **ignores pre-releases**. Either publish
   update-channel releases with `prerelease: false`, or host `latest.json` somewhere else (for
   example on therushd.com) and point `endpoints` there.
6. Updates are verified with the updater key. Users still need the OS-level code signing above
   for a smooth first install.

## Known limitations

- Requires internet; no offline mode beyond the "Can't reach Rushd" screen.
- The window title stays "Rushd" and does not follow the page title.
- Multiple instances are allowed; `tauri-plugin-single-instance` could be added if that matters.
- The Tauri CLI warns that `com.therushd.app` ends in `.app`. That is only a recommendation, so
  the identifier was kept as specified. Changing it later would move users' stored login
  session and web data, so decide before the first public release.
