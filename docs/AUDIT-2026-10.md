# Audit and plan (October 22, 2026)

Facts below were checked in the repository on this date. Assumptions are
marked as such.

## What exists

- **Stack:** Next.js 16 (App Router, server actions), React 19, Tailwind 4,
  Prisma 6 on Neon Postgres (WebSocket driver), Vercel hosting, Tauri v2
  desktop wrapper (`desktop/`). Vitest unit and integration tests, Playwright
  e2e, axe accessibility checks, and pixel/structure UI snapshots
  (`VISUAL=1`).
- **Auth:** email + password (hashed), httpOnly session cookie with a session
  version for "sign out everywhere", rate-limited signup/login/reset. Every
  mutation is scoped to the session's userId (`updateMany where {id, userId}`).
- **Courses (before this slice):** name, teacher, period, color, priority,
  archive/restore (non-destructive; delete is refused when a course has work).
  No level, school, code, subject, term, or workload fields; no catalog.
- **Planning:** deterministic scoring + scheduler (`src/lib/planning`),
  per-student time zone, availability windows, pinned blocks, workload
  forecast and "won't fit" warnings.
- **Learning evidence:** photo practice checks → assessments → mastery
  estimates with ranges and confidence; tutor grounded in synced course
  materials; draft feedback against Canvas rubrics. All AI behind
  `AIProvider` (`src/lib/ai/provider.ts`), server-side keys, metering,
  quotas, and a kill switch. **Not live in production:** no
  `ANTHROPIC_API_KEY` is configured.
- **Imports:** Canvas (token or calendar feed), Microsoft Teams (built, not
  configured), screenshot import with a review step (AI, so off in production).
- **Data rights:** account deletion exists (Settings). There is no data export.
- **Observability:** console logs only; no request/correlation IDs. Cron runs
  are recorded in the database and shown on /admin.
- **Brand:** the agreed Arabic logo is in the repo and used site-wide:
  `RushdLogo` in `src/components/brand/rushd-mark.tsx` (the Path mark,
  "Rushd" in Newsreader, and رُشد in Amiri Bold). It was created and approved
  in this project's earlier sessions; no change is needed or made.

## Risks found

1. **Migration history can't rebuild the database from scratch.**
   `20261021220000_course_content_tutor_reviews` alters `CanvasCourse`, which
   is created in `20261022024500_canvas_integration_and_schedule_blocks` (a
   later timestamp). Production is fine because it applied them in the order
   they were written; a fresh database fails at P3018. Fix (needs approval,
   touches production's migration records): rename the Canvas migration to an
   earlier timestamp and update `_prisma_migrations.migration_name` in
   production in the same change, or add a baseline. Until then, local
   databases are built with `scripts/setup-local-db.sh` (schema push + the
   hand-written SQL in `scripts/local-db-extras.sql`).
2. **Development and production shared one database.** Tests created and
   deleted their own users in production's Neon database. Now fixed for
   local work: `LOCAL_DB_PROXY` + `scripts/local-db-proxy.mjs` run everything
   against a local Postgres (all 80 integration and 42 e2e tests pass
   locally).
3. **The core learning loop depends on AI that is switched off in
   production.** The site says so plainly and hides AI features, but the
   product's main value isn't available to students until the key is set.
4. **No data export; no request IDs; logs are unstructured.**
5. **Two e2e tests only passed because the remote database was slow** (a
   navigation race and a loading-skeleton snapshot). Fixed.

## Prioritized plan

1. **Course setup and personalization (this slice, done).** Every later step
   (term-aware plans, per-course study goals, readiness, weekly insights)
   needs to know what each course is and when its term runs.
2. **Use the new course data in planning.** Stop scheduling a course after its
   term ends; show weekly study time against each course's goal; suggest
   archiving finished courses (never automatic).
3. **Syllabus and assignment import, preview-and-confirm.** File type/size
   validation, extracted dates with confidence, nothing saved until the
   student confirms; uncertain dates are never created silently. Reuses the
   screenshot-import review flow. Needs the AI key for extraction; the
   preview UI and validation can be built and tested with a scripted provider.
4. **Weekly insight** (completed work, skills that improved, what's uncertain,
   next week's plan) from existing study sessions and evidence, without
   shaming language.
5. **Exam readiness** as a transparent estimate (coverage, recency,
   confidence, time left), labeled as an estimate.
6. **Trust and operations:** data export (JSON), request IDs in logs,
   structured log helper that never logs content, fix the migration history.
7. **Mobile:** see `docs/IOS.md`.

## Why the first slice was chosen

It was the brief's suggested slice, and the code confirmed it was the right
foundation: courses had no level, term, or institution, so nothing downstream
could be personalized per course. It needs no AI and no syllabus parsing, and
it could be fully tested without production.
